# Aina RoleManager

Модульный Discord-бот с уведомлениями в Telegram. Discord- и Telegram-боты
работают в одном процессе с общей SQLite-базой; бот мультисерверный — каждый
Discord-сервер настраивается независимо.

**Ядро** (работает всегда): база данных, привязка Telegram-чатов к серверам,
доставка уведомлений. Привязка «многие-ко-многим»: к серверу можно привязать
несколько чатов (например, личные чаты нескольких администраторов), а в один
чат — получать уведомления нескольких серверов; в каждом уведомлении указано,
с какого сервера оно пришло.

**Модули** (включаются через `ENABLED_MODULES`):

| Модуль   | Что делает                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `roles`      | верификация новичков и именные роли через `/role`, импорт ранее созданных ролей |
| `mute_guard` | защита выбранных участников от server mute / server deafen с уведомлениями в Telegram                |

### Модуль `roles` — автоматическая выдача ролей

Новичок при входе получает роль «Не имеет ролей» и приглашение прописать `/role`.
В модальном окне он указывает название и цвет своей именной роли (и, по желанию,
кто его пригласил), затем может выбрать дополнительные роли из настроенного пула.
Бот создаёт именную роль, выдаёт обязательные роли, поздравляет в канале
[пинги], пишет в журнал и уведомляет привязанные Telegram-чаты. Если за 10 минут
участник не оформил роль — бот вежливо кикает его (не бан). Повторный вызов
`/role` владельцем именной роли открывает редактирование её имени/цвета.
Активные таймеры верификации переживают рестарт (восстанавливаются из БД).

Роли, созданные вручную или выданные до появления бота, можно привязать
к владельцам командой `/import-roles` — после этого они тоже редактируются
через `/role`.

### Модуль `mute_guard` — защита от мута

Если у кого-то на сервере есть право отключать микрофон/звук всем и он
пользуется им не по делу, администратор может взять участника под защиту
командой `/protect`. Пока защита действует, бот сразу снимает с участника
server mute и server deafen, а при включённых уведомлениях сообщает
в Telegram, кто пытался заглушить (по журналу аудита). Уведомления — не чаще
раза в 15 минут на участника; промолчанные попытки подсчитываются и попадают
в следующее уведомление. Собственные mute/deafen участника бот не трогает.

## Стек

- Python 3.11+
- [discord.py](https://discordpy.readthedocs.io/) 2.x (slash-команды, modals, select-меню)
- [aiogram](https://docs.aiogram.dev/) 3.x
- SQLite через aiosqlite (схема создаётся и мигрирует автоматически при старте)

## Установка

### 1. Создание Discord-бота

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application**.
2. Вкладка **Bot** → скопируйте **Token**.
3. Там же включите **Privileged Gateway Intents** → **SERVER MEMBERS INTENT**
   (обязательно — без него бот не увидит вход/выход участников и владельцев ролей).
   `MESSAGE CONTENT INTENT` не требуется: бот работает только на slash-командах.

### 2. Приглашение бота на сервер

Пригласите бота ссылкой (подставьте свой `CLIENT_ID` со вкладки OAuth2):

```
https://discord.com/api/oauth2/authorize?client_id=CLIENT_ID&permissions=415263874&scope=bot%20applications.commands
```

`permissions=415263874` включает:

| Право       | Модуль   | Зачем                                                                                                   |
| ---------------- | -------------- | ------------------------------------------------------------------------------------------------------------ |
| Manage Roles     | `roles`      | создание/выдача/редактирование именных ролей                         |
| Kick Members     | `roles`      | кик не прошедших верификацию                                                        |
| Send Messages    | `roles`      | напоминания, поздравления, журнал                                               |
| Manage Messages  | `roles`      | удаление собственных напоминаний                                               |
| View Channels    | все         | доступ к настроенным каналам                                                        |
| Embed Links      | `roles`      | embed-карточки                                                                                       |
| Manage Nicknames | `roles`      | опционально, на будущее                                                                  |
| Mute Members     | `mute_guard` | снятие server mute с защищённых участников                                        |
| Deafen Members   | `mute_guard` | снятие server deafen с защищённых участников                                      |
| View Audit Log   | `mute_guard` | определить, кто пытался заглушить (без него — «неизвестно») |

Если бот уже на сервере, приглашать заново не обязательно — достаточно выдать
его роли недостающие права в настройках сервера.

**Важно:** после приглашения перетащите роль бота в списке ролей сервера
**выше** всех ролей, которые он должен создавать и выдавать, — иначе Discord
не даст ему управлять ими. Бот предупредит в журнале, если иерархия нарушена.
Если в каком-то голосовом канале у роли бота отозвано право Mute/Deafen
Members, защита в этом канале не сработает — бот сообщит об этом в Telegram.

### 3. Создание Telegram-бота

Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
Если бот должен читать код привязки обычным сообщением в **групповом** чате,
отключите privacy mode: `/setprivacy` → Disable (или выдайте боту права
администратора группы).

### 4. Запуск

```bash
cp .env.example .env   # заполните DISCORD_TOKEN и TELEGRAM_TOKEN
```

**Docker (рекомендуется):**

```bash
docker compose up -d --build
```

База сохраняется в `./data/bot.db`.

**Без Docker:**

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
python -m bot.main
```

> Глобальные slash-команды появляются в Discord в течение ~часа после первого
> запуска. Для мгновенной синхронизации при разработке укажите `TEST_GUILD_ID`
> в `.env`.

## Первичная настройка сервера

1. **`/setup`** (только администратор) — настройка в два шага:
   - **шаг 1 (каналы):** выберите канал **[роли]** (приглашения новичков),
     канал **[пинги]** (поздравления) и канал **[журнал]** (лог событий),
     затем нажмите «Далее»;
   - **шаг 2 (роли):** выберите обязательные роли для новичков и, по желанию,
     существующую роль в качестве **«Не имеет ролей»** — если оставить поле
     пустым, бот найдёт её по имени или создаст автоматически. Нажмите
     «Сохранить».
2. **`/setup-optional-roles`** — задайте пул дополнительных ролей (до 25),
   которые новичок сможет выбрать при верификации. Необязательно.
3. **`/import-roles`** — если на сервере уже есть именные роли, созданные
   до бота, привяжите их к владельцам (см. ниже). Необязательно.
4. **`/connect`** — получите одноразовый код (действует 10 минут). Добавьте
   Telegram-бота в нужный чат (или напишите ему в личку) и отправьте туда код
   (`/start КОД` или просто сообщением). Бот подтвердит: «Чат привязан
   к серверу …». Повторите для каждого чата, который должен получать
   уведомления.

## Привязка Telegram

- **Несколько чатов на сервер:** каждый `/connect` выдаёт новый код; каждый
  использованный код добавляет ещё один чат, прежние привязки сохраняются.
- **Несколько серверов в чате:** отправьте в один чат коды с разных серверов.
  Каждое уведомление начинается со строки `🏰 Сервер «…»`.
- **Отвязка из Discord:** `/telegram-chats` — список привязанных чатов,
  выберите ненужные и нажмите «Отвязать».
- **Отвязка из Telegram:** `/unlink` в чате — кнопки с привязанными серверами
  (в группах доступно только администраторам чата). `/servers` — список серверов.
- **Перепривязка:** отвяжите старый чат и выполните `/connect` для нового.
- Если бота удалили из чата или заблокировали в личке, бот сам снимет
  привязки этого чата при следующей попытке отправки; если группа стала
  супергруппой — перенесёт привязки на её новый ID.

### Discord

| Команда            | Модуль   | Кому   | Что делает                                                                                                                                |
| ------------------------- | -------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/connect`              | ядро       | админ | код привязки Telegram-чата                                                                                                          |
| `/telegram-chats`       | ядро       | админ | список привязанных Telegram-чатов и их отвязка                                                                     |
| `/role`                 | `roles`      | всем   | новичку — оформление именной роли; владельцу — изменение имени/цвета своей роли |
| `/setup`                | `roles`      | админ | настройка каналов и обязательных ролей                                                                           |
| `/setup-optional-roles` | `roles`      | админ | пул дополнительных ролей для новичков                                                                             |
| `/import-roles`         | `roles`      | админ | привязка существующих ролей к владельцам                                                                       |

задаются прямо в сообщении через меню и кнопки. Публичные сообщения бот
пишет только в настроенные каналы [роли], [пинги] и [журнал].

| `/start КОД` | привязать чат к серверу (или просто код) |

## Как устроена верификация

1. `on_member_join`: роль «Не имеет ролей», запись в `pending_verifications`,
   приглашение в канале [роли].
2. Раз в 60 сек бот удаляет предыдущее напоминание и шлёт новое — всего 10 минут
   (настраивается через `VERIFICATION_TIMEOUT` / `REMINDER_INTERVAL`).
3. По истечении времени — кик (не бан) с записью в журнал. Если участник вышел
   сам — таймер останавливается; если зашёл заново — таймер стартует заново.
4. `/role` → модалка (название, HEX-цвет, кто пригласил) → выбор опциональных
   ролей (если настроены) → бот создаёт роль сразу под своей верхней ролью,
   выдаёт обязательные+выбранные роли, снимает «Не имеет ролей», поздравляет
   в [пинги], пишет в [журнал] и уведомляет Telegram.

**Ручная выдача ролей во время верификации.** Если кто-то вручную выдаёт
новичку обязательную роль или роль из пула дополнительных, пока тот не прошёл
`/role`, бот сразу снимает её, пишет в [пинги] администратору (найденному по
журналу аудита), что идёт верификация и через сколько минут участника
выпроводит, если он её не пройдёт, и отмечает событие в [журнал]. Остальные
роли не трогаются.

Выдача ролей устойчива к «уже выданным»: роли выдаются по одной, имеющиеся
и удалённые с сервера пропускаются, а сбой одной роли не срывает верификацию —
проблемные роли перечисляются в [журнал].

Владелец именной роли хранится в таблице `personal_roles`: у участника — одна
именная роль, у роли — один владелец.

## Импорт существующих ролей (`/import-roles`)

1. Выберите в меню до 25 ролей и нажмите «Проверить».
2. Бот сопоставит роли с носителями и покажет сводку:
   - ✅ у роли единственный носитель — он и станет владельцем;
   - ✅ *похоже по имени* — носителей несколько, но имя одного явно совпадает
     с названием роли;
   - ❔ носителей несколько или нет ни одного — нужен ваш выбор;
   - ☑️ роль уже привязана к своему носителю;
   - 🚫 роль не может быть именной: `@everyone`, роль бота/интеграции/бустеров,
     роль выше роли бота или роль из настроек верификации;
   - ⚠️ участник выбран для нескольких ролей — привяжется только первая.
3. «Разобрать спорные» — бот по очереди показывает каждую спорную роль
   со списком носителей: выберите владельца, подтвердите подсказку
   («Оставить и далее») или нажмите «Пропустить». Для роли без носителей
   можно выбрать любого участника — бот привяжет роль и выдаст её.
4. «Сохранить» — привязки записываются в БД (прежняя именная роль участника,
   если была, заменяется), событие попадает в [журнал].

## Защита от мута (`/protect`, `/unprotect`)

`/protect` открывает меню:

- **Пользователь** — кого защитить;
- **Время защиты** — готовые варианты от 15 минут до 7 дней, «бессрочно»
  или «Своё время…» — число минут (`-1` — бессрочно);
- **Уведомления в Telegram** — сообщать ли о попытках заглушить.

Повторный `/protect` для того же участника заменяет параметры защиты.
Если участник уже заглушён, бот снимет заглушение сразу. Истёкшие защиты
удаляются автоматически.

`/unprotect` показывает всех защищённых (срок, уведомления) и снимает защиту
с выбранных.

## Деплой на сервер (Docker)

Инструкция для Linux-сервера (Ubuntu/Debian). Предполагается, что код
опубликован в git-репозитории (GitHub/GitLab/Gitea — не важно).

### 0. Публикация кода (один раз, с рабочей машины)

Если проект ещё не в git:

```bash
cd d:\PythonBots\Aina_RoleManager
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/ВАШ_ЛОГИН/Aina_RoleManager.git
git push -u origin main
```

`.env` и `data/` в `.gitignore` — токены и база в репозиторий не попадут.

### 1. Установка Docker на сервере

```bash
# официальный скрипт Docker (ставит движок и compose-плагин)
curl -fsSL https://get.docker.com | sudo sh

# чтобы запускать docker без sudo (перелогиньтесь после этого)
sudo usermod -aG docker $USER
```

Проверка: `docker --version` и `docker compose version`.

### 2. Клонирование репозитория

```bash
git clone https://github.com/ВАШ_ЛОГИН/Aina_RoleManager.git
cd Aina_RoleManager
```

Для приватного репозитория используйте deploy key или personal access token:
`git clone https://ТОКЕН@github.com/ВАШ_ЛОГИН/Aina_RoleManager.git`.

### 3. Настройка окружения

```bash
cp .env.example .env
nano .env    # вписать DISCORD_TOKEN и TELEGRAM_TOKEN
```

### 4. Сборка и запуск

```bash
docker compose up -d --build
```

Compose соберёт образ из `Dockerfile` и запустит контейнер в фоне.
`restart: unless-stopped` уже прописан — после перезагрузки сервера
контейнер поднимется сам (если демон Docker в автозапуске:
`sudo systemctl enable docker`).

База SQLite лежит на хосте в `./data/bot.db` (volume) и переживает
пересборку контейнера.

### 5. Проверка и повседневные команды

```bash
docker compose logs -f          # логи (Ctrl+C — выйти, бот продолжит работать)
docker compose ps               # статус контейнера
docker compose restart          # перезапуск
docker compose down             # остановить и удалить контейнер (данные в ./data останутся)
```

В логах при успешном старте будут строки «Discord-бот вошёл как …» и
«Запускаю Discord- и Telegram-ботов…».

### 6. Обновление бота

```bash
cd Aina_RoleManager
git pull
docker compose up -d --build    # пересборка и перезапуск одним шагом
```

Схема БД мигрирует автоматически при старте. Перед обновлением на всякий
случай сделайте бэкап базы (см. ниже).

### 7. Бэкап базы

```bash
docker compose stop
cp data/bot.db ~/backups/bot-$(date +%F).db
docker compose start
```

## Структура проекта

```
bot/
  main.py                  # ядро: БД + оба бота в одном процессе (asyncio.gather)
  core/
    config.py              # конфиг из .env (в т.ч. ENABLED_MODULES)
    texts.py               # общие тексты (тон «горничной»), привязка Telegram
    utils.py
  db/
    database.py            # подключение и версионные миграции по модулям
    models.py              # схема ядра: telegram_links, connect_codes, action_log
    repository.py          # доступ к таблицам ядра (база для репозиториев модулей)
  discord_bot/
    bot.py                 # фабрика Discord-бота, загрузка модулей
    helpers.py             # общие хелперы ответов и проверки прав
    cogs/telegram_link.py  # /connect, /telegram-chats
  telegram_bot/
    bot.py                 # фабрика aiogram-бота
    handlers/link.py       # привязка/отвязка чатов: /start, /servers, /unlink
    notifier.py            # рассылка уведомлений во все чаты сервера
  modules/
    __init__.py            # реестр модулей (ModuleSpec)
    roles/                 # модуль «Автоматическая выдача ролей»
      cogs/                # verification.py, setup.py, import_roles.py
      views/               # modals.py, selects.py, import_roles.py
      models.py  repository.py  texts.py  notify.py
    mute_guard/            # модуль «Защита от мута»
      cog.py  views.py  models.py  repository.py  texts.py
```

### Как добавить модуль

1. Создайте пакет `bot/modules/<имя>/` с `MODULE = ModuleSpec(...)` в `__init__.py`:
   имя, название, список Discord-расширений и миграции БД.
2. Впишите пакет в `_REGISTRY` в `bot/modules/__init__.py` и, при желании,
   в `DEFAULT_MODULES` в `bot/core/config.py`.
3. Репозиторий модуля наследуйте от `bot.db.repository.Repository`, тексты
   держите в `texts.py` модуля, уведомления отправляйте через
   `bot.telegram_bot.notifier.notify_guild`.

### Миграции БД

Схема каждого модуля версионируется отдельно (таблица `schema_versions`),
недостающие миграции применяются при старте. Существующая база обновляется
автоматически: прежняя привязка Telegram переносится в `telegram_links`,
владельцы именных ролей — из `verification_log` в `personal_roles`.
